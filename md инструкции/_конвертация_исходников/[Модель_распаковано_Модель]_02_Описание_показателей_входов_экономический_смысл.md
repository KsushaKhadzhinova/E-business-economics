02. Входы: экономическое описание показателей

Русские эквиваленты, экономический смысл и роль показателей входного контура

> Назначение документа. Пояснить все показатели из предоставленной таблицы входов с экономической точки зрения и дать русские эквиваленты англоязычных сокращений. Перечень кодов и единиц измерения взят из исходной таблицы; экономические пояснения ниже являются аналитической интерпретацией назначения показателей в финансово-экономической модели цифрового бизнеса.

Ключ к обозначениям: ENV — внешняя среда; TAX — налоги/обязательные начисления; REV — выручка и объём продаж; COST — затраты; MKT — маркетинг; WC — оборотный капитал; HR — персонал; Q — квартал; PER — на единицу; FIXED — фиксированный; RATE — ставка/доля; SHARE — доля; BASE — базовый уровень; CAP — производительность/ёмкость; TXN — транзакция; SUBS — платные аккаунты/подписки.

| Код | Русский эквивалент | Экономический смысл | Единица измерения | Роль в модели / как интерпретировать |
|---|---|---|---|---|
| МАКРОЭКОНОМИКА И НАЛОГИ |  |  |  |  |
| ENV.INFLATION_Q | Квартальная инфляция | Темп общего роста цен за квартал. В модели служит внешним макроэкономическим фактором, который повышает номинальную стоимость индексируемых расходов и ставок. | % за квартал | Используется для индексации денежных ставок между периодами. Это не рост реального объёма затрат, а изменение их номинальной цены. |
| TAX.PAYROLL_RATE | Ставка начислений работодателя на оплату труда | Дополнительная нагрузка работодателя сверх начисленной заработной платы: обязательные начисления, связанные с фондом оплаты труда. Экономически показывает, насколько полная стоимость персонала выше его начисленной зарплаты. | % от оплаты труда | Входит в полную стоимость персонала. Значение поступает из блока 00; в этом блоке не должно задаваться независимо. |
| ВЫРУЧКА И МАСШТАБ ДЕЯТЕЛЬНОСТИ |  |  |  |  |
| REV.NET | Выручка без НДС | Стоимость проданных цифровых услуг и продуктов без косвенного налога. Это базовый показатель операционного дохода, с которым сопоставляют себестоимость, OPEX и маржинальность. | тыс. бел. руб. | Используется в отчёте о прибылях и убытках и большинстве показателей рентабельности. НДС не является доходом компании. |
| REV.GROSS | Выручка с НДС | Сумма начислений клиентам с учётом НДС. Экономически ближе к сумме счёта/платежа клиента, чем к доходу компании. | тыс. бел. руб. | Полезна для расчётов с покупателями и платёжными провайдерами, если комиссия взимается с полной суммы платежа. Не следует трактовать как чистый доход компании. |
| REV.TXN | Количество платных транзакций | Объём монетизируемых операций за период. Это натуральный драйвер транзакционной выручки и переменных затрат, возникающих на каждую операцию. | транзакций за квартал | Связывает рост клиентской активности с выручкой и затратами на инфраструктуру, API, сообщения, верификацию и другие операции на транзакцию. |
| REV.SUBS | Среднее число платных аккаунтов за квартал | Средняя активная платящая клиентская база за квартал. В отличие от числа аккаунтов на конец периода, отражает базу, которая фактически генерировала подписочную выручку в течение квартала. | аккаунтов | Основной объёмный драйвер подписочной выручки и затрат на аккаунт. Среднее за квартал снижает искажение при быстром росте клиентской базы внутри периода. |
| ОБЛАЧНАЯ ИНФРАСТРУКТУРА И ТРАНЗАКЦИОННЫЕ ЗАТРАТЫ |  |  |  |  |
| COST.CLOUD_FIXED_Q | Фиксированные расходы на облачную инфраструктуру и сеть доставки контента за квартал | Базовые расходы на облачные ресурсы, хостинг, резервные мощности и сеть доставки контента, которые возникают даже при небольшом объёме пользователей и транзакций. | тыс. бел. руб./квартал | Формируют условно-постоянную технологическую себестоимость. В заданном диапазоне нагрузки не зависят напрямую от числа аккаунтов и транзакций. |
| COST.CLOUD_PER_ACCOUNT | Облачные расходы на один платный аккаунт | Переменная или условно-переменная инфраструктурная стоимость обслуживания одного платного аккаунта за квартал. | бел. руб./аккаунт/квартал | Позволяет масштабировать инфраструктурные затраты вместе с подписочной клиентской базой и рассчитывать удельную маржинальность аккаунта. |
| COST.CLOUD_PER_TXN | Облачные расходы на одну транзакцию | Инфраструктурная стоимость обработки одной платной транзакции: вычисления, хранение, передача данных и иные ресурсы, масштабируемые с количеством операций. | бел. руб./транзакцию | Формирует переменную часть себестоимости транзакционной модели. Рост REV.TXN автоматически увеличивает эти расходы. |
| COST.PAYMENT_SHARE | Доля выручки, проходящая через платёжные каналы с комиссией | Часть валовой выручки, по которой компания действительно платит эквайринговую или иную платёжную комиссию. Учитывает, что часть клиентов может платить по каналам без такой комиссии. | % валовой выручки | Предотвращает начисление комиссии на 100% выручки, если платные каналы используются не для всех платежей. |
| COST.PAYMENT_RATE | Средняя ставка комиссии платёжного провайдера | Средневзвешенный процент, удерживаемый эквайером, платёжным агрегатором или иным провайдером за обработку платежей. | % от суммы платежей через комиссионные каналы | В сочетании с COST.PAYMENT_SHARE определяет платёжные расходы. Экономически это переменная стоимость получения денежных средств от клиента. |
| COST.API_PER_TXN | Расходы на внешние программные интерфейсы, сообщения и верификацию на транзакцию | Удельные внешние расходы, возникающие при каждой операции: обращения к сторонним API, SMS/сообщения, проверка данных, идентификация и другие сервисы. | бел. руб./транзакцию | Прямая переменная себестоимость транзакции. Особенно важна для цифровых сервисов, использующих платные внешние инфраструктурные компоненты. |
| COST.CONTENT_FIXED_Q | Фиксированные расходы на лицензии на контент и данные | Периодические лицензионные платежи за право использовать контент, базы данных или информационные ресурсы независимо от текущего числа клиентов. | тыс. бел. руб./квартал | Условно-постоянная часть себестоимости цифрового продукта, если доступ к данным или контенту лицензируется фиксированным платежом. |
| COST.CONTENT_PER_ACCOUNT | Расходы на контент и данные на один платный аккаунт | Лицензионные или иные платежи за контент/данные, которые изменяются пропорционально числу платящих аккаунтов. | бел. руб./аккаунт/квартал | Переменная себестоимость подписки. Нужна для оценки валовой маржи на одного платного клиента. |
| МАРКЕТИНГ И КЛИЕНТСКАЯ БАЗА |  |  |  |  |
| MKT.CHURN_Q | Квартальный отток платных аккаунтов | Доля платящих аккаунтов, которые прекращают оплату или покидают сервис в течение квартала. Это показатель удержания клиентской базы. | % активных платных аккаунтов за квартал | Чем выше отток, тем больше новых клиентов требуется только для сохранения текущего масштаба. Здесь речь именно об оттоке аккаунтов, а не об оттоке выручки. |
| MKT.CAC | Стоимость платного привлечения одного аккаунта | Средняя стоимость получения одного нового платного аккаунта через платные каналы привлечения. CAC = customer acquisition cost, по-русски — стоимость привлечения клиента/аккаунта. | бел. руб./новый платный аккаунт | Используется для расчёта переменной части расходов на привлечение. Следует контролировать, чтобы затраты, уже включённые в CAC, не дублировались в базовом маркетинговом бюджете. |
| MKT.LAUNCH_PAID_SHARE | Доля стартовой клиентской базы, привлечённая платными каналами | Часть клиентов на этапе запуска, для привлечения которых потребовались платные маркетинговые или продажные каналы. | % стартовой клиентской базы | Позволяет не считать всю стартовую базу платно привлечённой. Органические, партнёрские и иные бесплатные/условно бесплатные источники отделяются от платного привлечения. |
| MKT.BASE_Q | Базовые расходы на результативный и имиджевый маркетинг за квартал | Постоянный или условно-постоянный маркетинговый бюджет на поддержание спроса, бренда, контента, рекламы и присутствия на рынке. Performance marketing — маркетинг, ориентированный на измеримый результат; brand marketing — маркетинг бренда. | тыс. бел. руб./квартал | Формирует базовый OPEX маркетинга независимо от конкретного числа новых аккаунтов. Нужен контроль на отсутствие двойного счёта с CAC. |
| ПРОГРАММНЫЕ, ЗАЩИТНЫЕ И АДМИНИСТРАТИВНЫЕ РАСХОДЫ |  |  |  |  |
| COST.SOFTWARE_Q | Расходы на программные сервисы и лицензии за квартал | Затраты компании на сторонние программные инструменты: системы управления, аналитики, разработки, коммуникаций и другое программное обеспечение как услуга (SaaS). | тыс. бел. руб./квартал | Операционные расходы на внутренний технологический контур бизнеса. Обычно условно-постоянные или ступенчато растущие при расширении команды. |
| COST.SECURITY_Q | Расходы на кибербезопасность и соблюдение обязательных требований | Затраты на защиту данных и инфраструктуры, мониторинг, аудит, сертификацию, процедуры соответствия требованиям (compliance) и связанные сервисы. | тыс. бел. руб./квартал | Для цифрового бизнеса это отдельный OPEX, который может расти ступенчато при увеличении масштаба, числа клиентов и требований к контролю. |
| COST.ADMIN_Q | Прочие административные расходы за квартал | Общехозяйственные расходы, не отнесённые напрямую к продукту, маркетингу, инфраструктуре или персоналу: офисные, профессиональные, организационные и иные административные затраты. | тыс. бел. руб./квартал | Формируют общие операционные расходы. Важно не включать сюда затраты, уже учтённые в других строках модели. |
| ОБОРОТНЫЙ КАПИТАЛ И СРОКИ РАСЧЁТОВ |  |  |  |  |
| WC.PREPAID_RATE | Доля авансовой оплаты поставщикам облачных, программных и защитных сервисов | Часть соответствующих расходов, оплачиваемая поставщикам заранее. Экономически создаёт предоплаченные расходы: деньги уходят раньше, чем затрата полностью признаётся в периоде. | % соответствующих расходов | Влияет прежде всего на денежный поток и оборотный капитал, а не на размер экономического расхода сам по себе. |
| WC.DPO_DAYS | Средний срок оплаты поставщикам | Среднее количество дней между возникновением обязательства перед поставщиком и его фактической оплатой. DPO = days payable outstanding, по-русски — срок погашения кредиторской задолженности поставщикам. | дней | Чем больше DPO, тем дольше компания финансирует часть деятельности за счёт кредиторской задолженности и тем позже происходит денежный отток. |
| WC.STAFF_ACCRUAL_DAYS | Среднее число дней начисленной, но ещё не выплаченной заработной платы | Временной разрыв между признанием расходов на персонал и выплатой денежных средств сотрудникам. | дней | Формирует задолженность перед персоналом на конец периода и сдвигает часть денежного оттока на следующий период. |
| ПЕРСОНАЛ И ПРОИЗВОДИТЕЛЬНОСТЬ |  |  |  |  |
| HR.SUPPORT_BASE_FTE | Базовая численность команды поддержки в эквиваленте полной занятости | Минимальное число сотрудников поддержки, необходимое для работы сервиса независимо от текущего объёма клиентов. FTE = full-time equivalent, по-русски — эквивалент полной занятости. | FTE | Фиксированная кадровая база функции поддержки. Дополнительные сотрудники добавляются при превышении расчётной нагрузки. |
| HR.SUPPORT_ACCOUNT_CAP | Производительность сотрудника поддержки по платным аккаунтам | Количество платных аккаунтов, которое способен обслуживать один дополнительный сотрудник поддержки при заданном уровне сервиса. | аккаунтов/FTE | Драйвер масштабирования команды поддержки. Чем меньше показатель, тем быстрее растёт необходимая численность при увеличении клиентской базы. |
| HR.SUPPORT_TXN_CAP | Производительность сотрудника поддержки по транзакциям | Количество транзакций, которое может приходиться на одного дополнительного сотрудника поддержки за расчётный период. | транзакций/FTE | Дополнительный драйвер нагрузки поддержки. Если одновременно используются аккаунты и транзакции, модель должна чётко определить способ объединения двух нагрузок, чтобы не удваивать численность. |
| HR.INFRA_BASE_FTE | Базовая численность инфраструктурной команды в эквиваленте полной занятости | Минимальная команда, обеспечивающая эксплуатацию платформы, облачной инфраструктуры, надёжность и техническое сопровождение. Infra = infrastructure, по-русски — инфраструктура. | FTE | Фиксированный кадровый минимум технологической эксплуатации, необходимый ещё до значительного масштабирования бизнеса. |
| HR.INFRA_ACCOUNT_CAP | Производительность инфраструктурной команды по платным аккаунтам | Количество платных аккаунтов, которое может обслуживаться одним дополнительным инфраструктурным FTE при заданной архитектуре и уровне автоматизации. | аккаунтов/FTE | Используется как порог для увеличения инфраструктурной команды по мере роста клиентской базы. |
| HR.INFRA_TXN_CAP | Производительность инфраструктурной команды по транзакциям | Количество транзакций, которое может поддерживаться одним дополнительным инфраструктурным FTE. | транзакций/FTE | Отражает операционную масштабируемость технологической платформы. При использовании вместе с аккаунтным драйвером требуется правило объединения нагрузок. |
| HR.SALES_BASE_FTE | Базовая численность команды продаж в эквиваленте полной занятости | Минимальное число сотрудников продаж, необходимое для построения и обслуживания процесса привлечения клиентов. Sales = продажи. | FTE | Фиксированная кадровая база коммерческой функции, существующая независимо от текущего числа новых клиентов. |
| HR.SALES_ACQ_CAP | Производительность одного сотрудника продаж по привлечению платных аккаунтов | Количество новых платных аккаунтов, которое один сотрудник продаж способен привлечь или обработать за квартал. ACQ = acquisition, по-русски — привлечение. | аккаунтов/FTE за квартал | Определяет требуемое масштабирование отдела продаж при росте плана привлечения. Это показатель производительности/ёмкости, а не стоимость привлечения. |
