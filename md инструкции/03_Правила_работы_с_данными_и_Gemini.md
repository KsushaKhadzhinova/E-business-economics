# Правила работы с данными и промптами Gemini

## Единицы и формат

- Деньги модели — **тыс. BYN** (500 = 500 000 BYN). Если исходные данные в BYN — разделить на 1000 до ввода. (Упрощённый дашборд 01–07 — в BYN.)
- Проценты вводятся **долями**: 20% = 0,20.
- Цены и выручка — без НДС; НДС считается отдельно через `TAX.VAT_RATE`.
- Не смешивать значения «на конец периода» и «среднее за квартал».

## Что редактировать, а что нет

1. Только ячейки ввода (жёлтые, синий шрифт) и межфайловый перенос.
2. Расчётные строки не заменять числами; технические коды не переименовывать.
3. Порядок обновления: 00 → 01/02 → 03 → 04 → 05 → 06 → 07, после каждого шага — лист «Контроль».
4. Не переносить в блок 00 драйверы функциональных блоков (CAC, churn, FTE, CAPEX).

## Работа с Gemini (бесплатная версия)

- Excel в Gemini **не загружать**. Один короткий запрос — одно сообщение. В начало вставлять заполненную бизнес-постановку (`04_Шаблон_бизнес-постановки.md`).
- В следующий шаг вставлять только нужный результат предыдущего, не весь чат.
- Если надёжных данных нет — корректный ответ «НЕТ НАДЕЖНЫХ ОТКРЫТЫХ ДАННЫХ» + proxy/assumption с явной маркировкой.
- Расчёты выполняет Excel; Gemini готовит исходные данные и доказательства.
- Для каждого внешнего числа: значение, единица, период, география, источник, дата, прямой URL; тип FACT / BENCHMARK / PROXY / ASSUMPTION / INTERNAL.
- Приоритет источников: НПА/регулятор/статистика → первичный сайт поставщика/отчётность → отраслевое исследование → профессиональный benchmark; блоги и агрегаторы — только как навигация.
- Не выдумывать URL, дату, цитату, число. Не смешивать страны, стадии, B2B/B2C.
- Для стартапа собственные CAC, churn, conversion, usage до запуска — BENCHMARK/PROXY/ASSUMPTION; после запуска заменяются на ACTUAL.

## Верификация выдачи перед переносом в Excel

| Шаг | Действие |
|---|---|
| 1 Доступность | Открыть каждый URL; не открывается — источник отклонён |
| 2 Соответствие | Найти на странице именно это число/правило |
| 3 Контекст | Дата, география, валюта, НДС, период, единица, объект (клиент/аккаунт/транзакция) |
| 4 Методика | Проверить знаменатель и определение (CAC ≠ CPL, churn с периодом) |
| 5 Первичность | Найти первоисточник вместо вторичного материала |
| 6 Триангуляция | Для важного benchmark — второй независимый ориентир |
| 7 Решение | VERIFIED / PARTLY VERIFIED / REJECTED; переносить VERIFIED или явный proxy/assumption |

Если Gemini обрывает ответ: «Продолжи только с места остановки. Не повторяй предыдущий текст и не меняй уже приведённые значения».

## Типовые ошибки

Ввод 20 вместо 0,20; ввод BYN вместо тыс. BYN; перенос по названию, а не по коду; смешение с НДС и без НДС; двойной учёт расхода в двух блоках; изменение одного файла без обновления следующих; игнорирование листа «Контроль»; ручной пересчёт коэффициентов 07; смешение Project IRR и Investor IRR.

## Финальный чек-лист работы

- [ ] Ручные значения подтверждены источником и в правильной единице
- [ ] Межфайловые строки совпадают по коду и периоду
- [ ] Формулы не заменены числами
- [ ] Налоги и правовые предпосылки проверены на дату модели
- [ ] Все проверки «Контроль» = OK или объяснены
- [ ] Выходы обновлены и перенесены в следующий файл
