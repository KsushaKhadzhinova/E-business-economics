# Блок 02. Команда и OPEX (+ 02-1 команда по ТЗ)

**Цель.** Рассчитать штат (FTE), ФОТ, начисления, COGS, OPEX, маркетинг, облако/API/платежи, часть оборотного капитала и затраты для безубыточности. 02-1 переводит ТЗ сайта в трудоёмкость, FTE, Headcount и ФОТ команды разработки.

**Получает данные из:** 00: инфляция, начисления; 01: аккаунты, транзакции, выручка.

**Передаёт данные в:** 02 → 03 (AP, prepaids, payroll accrual), 05 (COGS, OPEX, ФОТ), 06 (break-even costs).

**Листы Excel:** Входы, Команда (частично ручной), OPEX (авторасчёт), Выходы, Связи, Контроль.

**Ключевые коды (ручной ввод/основные):** `HR.DEV_HC, HR.DEV_SAL0, HR.INFRA_SAL0, HR.SUPPORT_SAL0, HR.ADMIN_HC, HR.ADMIN_SAL0, HR.SALES_SAL0; а также MKT.CAC, MKT.CHURN_Q, COST.CLOUD_*, COST.API_PER_TXN, COST.PAYMENT_*`

**Правила и ловушки:** Зарплаты — в ценах 1-го квартала (индексация автоматически). Команда продаж и поддержки считается от capacity (HR.SALES_ACQ_CAP, HR.SUPPORT_*_CAP). Расчётные строки не заменять. FTE ≠ Headcount.

**Куда используется в курсовой (бизнес-план):** Организационный план (численность, ФОТ), производственный/операционный план (cloud, API, payment, COGS), маркетинговый бюджет.

## Порядок выполнения

1. Заполнить `Шаблон_входных_данных.md` (бизнес-постановка + входные данные с источниками). Сбор данных — по промптам Gemini из папки `md/` (один запрос — одно сообщение; Excel в Gemini не загружать).
2. Проверить найденные данные: открыть URL, сверить число, дату, единицу, географию; присвоить статус VERIFIED / PARTLY / REJECTED. Переносить в Excel только VERIFIED или явно помеченный PROXY/ASSUMPTION.
3. Внести значения в Excel только в ячейки ввода (жёлтые с синим шрифтом). Технические коды не переименовывать, расчётные формулы не заменять числами.
4. Обновить связанные блоки в направлении 00 → 01/02 → 03 → 04 → 05 → 06 → 07.
5. Открыть лист «Контроль» — все проверки должны быть OK (либо ВНИМАНИЕ с осознанным комментарием).
6. Выписать итоговые показатели для текста бизнес-плана (см. `../../md инструкции/02_Матрица_сборки_бизнес-плана.md`).

## Подробный алгоритм

1. **ТЗ DSLKit → 02-1.** В `02-1_Модель_расчета_команды_разработки_по_ТЗ.xlsx` пройдите листы по порядку:
   - `01_Параметры`: длительность проекта, часы 1 FTE в месяц, резервы, PM, code review, исправление дефектов, дата старта;
   - `02_Функции_ТЗ`: замените 10 примерных функций функциями DSLKit (регистрация/вход/роли, редактор DSL с проверкой, рендеринг через Kroki, экспорт SVG/PNG, проекты и история версий, тарифы и квоты, **платёжная интеграция (эквайринг)**, **выбор валюты отображения**, администрирование, журнал запросов); для каждой выберите тип, сложность, интеграцию, дизайн;
   - `03_Нормативы`: подтвердите часы на функцию (калибровка по вашим прошлым работам);
   - `04_Трудоемкость` → `05_Команда` (FTE, Headcount) → `06_ФОТ` (зарплаты по ролям — подтвердите рынком) → `07_Дашборд`.
2. **Перенос в файл 02:** листы «Команда» (`HR.DEV_HC`, `HR.DEV_SAL0`, `HR.INFRA_*`, `HR.SUPPORT_*`, `HR.ADMIN_*`, `HR.SALES_*`) и «Входы» (`COST.CLOUD_FIXED_Q`, `COST.CLOUD_PER_ACCOUNT`, `COST.API_PER_TXN`, `COST.PAYMENT_SHARE`, `COST.PAYMENT_RATE`, `MKT.CAC`, `MKT.CHURN_Q`, `COST.CONTENT_*`).
3. **Эквайринг:** `COST.PAYMENT_RATE` — процент провайдера (по договору/тарифам), `COST.PAYMENT_SHARE` — доля выручки, проходящая через платёжные каналы (для Enterprise — по счёту, без комиссии).
4. Лист «OPEX» — автоматический: проверьте COGS, OPEX, EBITDA по кварталам.
5. «Контроль» → OK (колонка X); план привлечения клиентов не должен превышать capacity продаж/поддержки.

### Что собрать самостоятельно
Прайсы облака (Render/AWS/Hetzner), условия эквайринга, зарплатные вилки (ПВТ/ЕС), стоимость SaaS-инструментов, юридические и бухгалтерские услуги.
